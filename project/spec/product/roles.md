# Спецификация ролей пользователей (Roles & RBAC)

В соответствии с методическими требованиями к НИРС и дополнениями преподавателя («должно быть не менее 2 пользователей: админ и юзер»), в системе MedAI определены две роли: **Пользователь** (`User`) и **Администратор** (`Admin`).

---

## 1. Роль 1: Пользователь (User)

Конечный потребитель сервиса, использующий личный кабинет для инвентаризации домашней аптечки и обращения за доврачебной помощью.

### 1.1. Персона пользователя
- **Имя:** Алексей, 29 лет.
- **Контекст:** Хранит дома разнородный набор лекарств в коробке. При возникновении боли или температуры хочет быстро понять, что из имеющегося дома безопасно принять, в какой дозе и с какими ограничениями.

### 1.2. Функциональные возможности
- **Аутентификация:** регистрация по Email и паролю, авторизация с сохранением сессии в `localStorage`.
- **Управление профилем:** просмотр и редактирование личных данных (имя, контактный email, фото профиля).
- **Инвентаризация аптечки:**
  - Просмотр списка препаратов с тегами назначения.
  - Поиск лекарств по названию.
  - Добавление нового препарата через модальное окно.
  - Удаление израсходованного препарата с подтверждением.
  - Выбор препаратов кликом для прикрепления к контексту запроса.
- **Диалог с ассистентом:**
  - Отправка текстовых вопросов по симптомам и препаратам.
  - Получение структурированного ответа (рекомендованный препарат из наличия, дозировка по официальной инструкции, противопоказания, предупреждения).

---

## 2. Роль 2: Администратор базы знаний (Admin)

Специалист, ответственный за актуальность, полноту и валидность корпуса официальных медицинских инструкций и качество информационного поиска BM25.

### 2.1. Персона администратора
- **Имя:** Тимур, куратор медицинской базы данных / тимлид проекта.
- **Контекст:** Контролирует, чтобы в поисковый индекс попадали исключительно проверенные инструкции Минздрава РФ, а показатели поискового движка соответствовали академическим критериям НИРС.

### 2.2. Функциональные возможности
- **Управление корпусом инструкций:** добавление новых структурированных аннотаций лекарственных средств, обновление и удаление устаревших документов.
- **Управление поисковым индексом:** просмотр параметров корпуса ($N$, $|V|$, $avgdl$), инициация переиндексации алгоритма BM25.
- **Бенчмаркинг качества:** запуск тестовых прогонов по эталонному датасету (45 запросов) и мониторинг метрик $MRR$ и $Recall@k$.

## 3. Матрица разграничения доступа (RBAC Matrix)

| Объект / Действие | Пользователь (`User`) | Администратор (`Admin`) |
|---|:---:|:---:|
| Регистрация и авторизация в системе | Разрешено | Разрешено |
| Просмотр и редактирование личного профиля | Разрешено | Разрешено |
| Ведение домашней аптечки (просмотр, добавление, удаление) | Разрешено | Разрешено (в своей аптечке) |
| Отправка симптоматических запросов в диалог | Разрешено | Разрешено |
| Просмотр чужих домашних аптечек | Запрещено | Запрещено (приватность данных) |
| Просмотр полного реестра корпуса медицинских инструкций | Запрещено | Разрешено |
| Добавление и удаление документов корпуса | Запрещено | Разрешено |
| Запуск переиндексации поискового алгоритма BM25 | Запрещено | Разрешено |
| Запуск бенчмарка и просмотр метрик качества (MRR, Recall@k) | Запрещено | Разрешено |

---

## 4. Отражение ролей в интерфейсе

- Пользователь взаимодействует с клиентским веб-приложением [ui/site.html](../../ui/site.html) после авторизации через [ui/auth.html](../../ui/auth.html).
- Администраторские операции управления корпусом и мониторинга бенчмарка формализованы в виде сервисных контрактов API в [spec/tech/api.md](../tech/api.md).
