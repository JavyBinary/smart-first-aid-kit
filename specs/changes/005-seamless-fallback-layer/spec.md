# 005-seamless-fallback-layer: Архитектура двойного режима Seamless Fallback

## Цель
Обеспечить независимую разработку фронтенда (Катя) и бэкенда (Лука) за счет внедрения в клиентский код архитектуры Seamless Fallback: автоматическое переключение на локальный демо-режим при недоступности сервера FastAPI.

## Требования
- REQ-001: Зафиксировать единый базовый адрес API: `http://localhost:8000/api/v1`.
- REQ-002: Все клиентские запросы (`fetch`) оборачиваются в асинхронные блоки с перехватом сетевых ошибок `catch`.
- REQ-003: При отсутствии соединения (`Failed to fetch`) клиент плавно активирует локальный демонстрационный режим с идентичной структурой Pydantic-ответа.
- REQ-004: На стороне FastAPI зафиксировано обязательное требование конфигурации `CORSMiddleware`.

## Критерии приемки
- [x] При выключенном FastAPI интерфейс функционирует автономно без ошибок в консоли.
- [x] При включенном FastAPI клиент обращается к реальным эндпоинтам бэкенда без правок кода.
